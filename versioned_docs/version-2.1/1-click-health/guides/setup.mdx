### 1-Click Health Settings

**Click the 1-Click Health tab to access these settings.**


#### Check After Autofill

<Admonition type="note" title="Definitions">
    **Autofill** and **check** are the two core capabilities of 1-Click Health:
    - Insurance **autofill**: Autofilling a user's insurance info based on their PII (Name, Birthday, etc.) and optionally payer.
    - Eligibility **check**: Running an eligibility check for the user's insurance. 
</Admonition>

<Admonition type="info">
    This setting determines a default value, which you can override anytime by including `checkAfterAutofill` in the request body of [`POST /1-click/health`](/reference/api/endpoints#post-1-clickhealth).
</Admonition>

**Choose whether to automatically run an eligibility check for a user's insurance after we successfully autofill it:**

<table>
    <tr>
        <th>Option</th>
        <th>Description</th>
    </tr>
    <tr>
        <td>On <Chip label="Recommended" variant="outlined" size="small" color="primary"/></td>
        <td>Automatically run eligibility check after autofill</td>
    </tr>
    <tr>
        <td>Off</td>
        <td>Don't automatically run eligibility check after autofill</td>
    </tr>
</table>

If you set this to **On**, we will run an eligibility check and return full insurance details: a 271 in raw and parsed form.

<Admonition type="tip" title="We Recommend Setting This to On">
    Most use cases require running an eligibility check for the user's insurance. We can do this automatically for you, after autofilling the insurance, so you don't have to make another API call to do it.
</Admonition>


#### Service Type Codes

> A **service type code** is an [X12](https://x12.org/codes/service-type-codes) code that identifies business groupings for health care services or benefits.

<Admonition type="info">
    This setting determines a default value, which you can override anytime by including `serviceCodes.serviceTypeCodes` in the request body of [`POST /1-click/health`](/reference/api/endpoints#post-1-clickhealth).
</Admonition>

**Optionally, choose which service type codes to include in the health insurance lookup** (in the EDI 270). The most general code (`30`, for Plan Coverage and General Benefits) is included by default. See the full list of service type codes below.

:::warning
We don't recommend changing the default unless you have a specific reason and know what you're doing. In general, shorter lists produce more reliable results.
:::

#### Coverage Types

> A **coverage type** is a type of health insurance plan that we determine based on the full insurance details (in the EDI 271), which are available when an eligibility check is run.

<Admonition type="info">
    Coverage types are included in outputs (as `coverageTypes` in a [`1ClickHealthEntity`](/reference/api/types#1clickhealthentity)).
</Admonition>

**Choose one or more coverage types to filter output health insurance plans by.** All are included by default, and you must have at least one selected.

    <tr>
        <th>Option</th>
        <th>Description</th>

#### Network Rules

> A **network rule** defines the network status of a health insurance plan: whether you consider that plan in or out of network, based on various conditions you define.

<Admonition type="info">
    [Network decisions](/reference/data/outputs#network-decision) are included in outputs (as the `network` object in a [`1ClickHealthEntity`](/reference/api/types#1clickhealthentity)), when an eligibility check is run and at least one network rule is defined.
</Admonition>

<Admonition type="info" title="The Webhook is Optional">
    Using a webhook is optional: it's just one way to receive [output](/reference/data/outputs#1-click-health) 1-Click Health data. You can alternatively poll the [`GET /1-click/health`](/reference/api/endpoints#get-1-clickhealth) endpoint to achieve the same thing.
</Admonition>

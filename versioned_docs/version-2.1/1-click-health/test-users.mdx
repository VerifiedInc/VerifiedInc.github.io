You can test 1-Click Health with mock data in [Sandbox](/reference/api/environments#sandbox), using either random inputs or our dedicated test users below.

**These test users are keyed on first name, last name, and birth date.** Birth date is the unique input that distinguishes one test user from another, so always send the documented one. Every test user has plans with **real payers** (the payer `ids` work in other systems), and every plan returns the same information whether you use insurance autofill or an eligibility check.

<DevelopmentWorkAdmonition />

:::info What you get back
- **Always:** `memberId`, `payer`, `coverageTypes`, `serviceTypeCodes`, and `isMedicare` for each plan.
- **With an eligibility check** (the [Check After Autofill](/1-click-health/guides/setup#check-after-autofill) brand setting, `checkAfterAutofill: true` in the request, or `memberId` + `payer` as inputs): also the raw `edi_271`, the parsed [`eligibility`](/reference/api/types#parsededi271) with every field populated (plan name, group number and name, insurance type codes, member address, benefits, contacts), and `network` when your brand has [Network Rules](#network-rules).
- **At most two plans** are returned per lookup.
- Your brand's [Coverage Types](/1-click-health/guides/setup#coverage-types) and [Service Type Codes](/1-click-health/guides/setup#service-type-codes) settings filter plans: see [Brand settings that hide test users](#brand-settings-that-hide-test-users).
:::


## How to Use Test Users

{/* Need to be updated when we have support in the Demo and SDK */}

### API

1. Access the [Dashboard](https://dashboard.verified.inc) and go the Brand Details page for your brand.
2. Copy a [Sandbox](/reference/api/environments#sandbox) API key for your brand.
3. Call [`POST /1-click/health`](/reference/api/endpoints#post-1-clickhealth) with the test user's info (varies by user).
4. Receive output data via webhook or by polling the [`GET /1-click/health`](/reference/api/endpoints#get-1-clickhealth) endpoint.

:::

### Eligibility Check

An eligibility check sends `memberId` and `payer`. Which inputs the test user is matched on depends on the user:

**Matched on member ID.** Send the member ID and payer below; first name, last name and birth date can be anything (they are echoed back in the 271). Every plan in the Success tables works the same way with its own member ID and payer.

| Outputs | Member ID | Payer |
| --- | --- | --- |
| Active coverage | `W345876123` | Aetna (`60054`) |
| Active coverage | Any member ID from the Success tables | That plan's payer |
| Inactive coverage (`coverageStatus: "inactive"`) | `INACTIVE60054` | Aetna (`60054`) |
| No coverage (subscriber not found) | `NOTFOUND001` | Aetna (`60054`) |

**Matched on name and birth date.** Send these exactly, with the payer; the member ID can be anything.

| Outputs | Birth Date | First Name | Last Name | Payer |

## Eligibility Check

To test an **[eligibility check](/1-click-health/guides/api-integration#eligibility-check)** instead of insurance autofill, send `memberId` and `payer` along with the user's PII. Any plan above works with its member ID and payer ID (for example Richard Hendricks with `memberId: "A484069"` and `payer: { "id": "60054" }`). Include `checkAfterAutofill: true`, or have the brand setting on, to receive `edi_271` and `eligibility`.

The following users exist only on this path:

| First Name | Last Name | Birth Date | Payer | Member ID | Result |
| --- | --- | --- | --- | --- | --- |
| Jane | Doe | 1985-04-12 | Aetna (`60054`) | `W345876123` | Active coverage, AETNA CHOICE POS II |
| Bertram | Gilfoyle | 1995-08-19 | Blue Cross Blue Shield of Michigan (`00710`) | Any value | Active coverage |
| Bertram | Gilfoyle | 1990-01-01 | Anthem Blue Cross Blue Shield of New York (`803`) | Any value | Active coverage |
| Bertram | Gilfoyle | 1980-03-03 | Cigna (`62308`) | Any value | Active coverage |
| Jane | Doe | 1970-01-01 | Aetna (`60054`) | `INACTIVE60054` | Inactive coverage, AETNA CHOICE POS II terminated 2023-12-31 (`coverageStatus: "inactive"`) |
| Jane | Doe | 1985-04-12 | Aetna (`60054`) | `NOTFOUND001` | No coverage found (subscriber not found) |

Any other member ID and payer returns "No coverage found".

An inactive plan is still a result: the payer answered about the member you named, so the request succeeds and the plan comes back with `eligibility.coverageStatus` set to `"inactive"` (and the termination date in `eligibility.plan.terminationDate`). Only an unknown member fails with "No coverage found". Insurance autofill never returns inactive plans.

## Brand Settings That Hide Test Users

Two brand settings filter plans after the payer answers, so a test user can legitimately return "No coverage found" on your brand:

- **[Coverage Types](/1-click-health/guides/setup#coverage-types)** set to Medical only removes the dental and vision plans: Dinesh Chugtai and Jared Dunn return no coverage, Erlich Bachman returns his medical plan only.
- **[Service Type Codes](/1-click-health/guides/setup#service-type-codes)** narrow the question. A plan is dropped when every specific code it answers is outside your list; the plan-level code `30` never filters. With the default (`30`) every user returns; with `30` and `98` the medical users return and the dental / vision users do not; with `30` and `35` only the dental plans return.

## Network Rules

[Network Rules](/1-click-health/guides/setup#network-rules) belong to your brand, not to the test user, and the `network` object is only returned when an eligibility check ran. To see every outcome, create these rules on your Sandbox brand in the Dashboard:

| Rule | Status | Test users it matches |
| --- | --- | --- |
| Payer equals Aetna (`V404110`) and Insurance Type Codes include `PR` | In Network | Richard Hendricks (Aetna), Erlich Bachman (Aetna) |
| Payer equals UnitedHealthcare (`V816685`) | Out of Network | Richard Hendricks (UnitedHealthcare) |
| Payer equals Cigna (`V253146`) and State equals `TX` | In Network | Russ Hanneman |
| Insurance Type Codes include `MA`, `MB`, `HN` | In Network | Peter Gregory, Jack Barker (Medicare), Ron LaFlamme |
| Insurance Type Codes include `MC`, notes "Self-pay" | Out of Network | Jack Barker (Medi-Cal) |
| Insurance Type Codes include "No insurance type code" | Indeterminate | Monica Hall, Nelson Bighetti, Dinesh Chugtai, Jared Dunn, Erlich Bachman (dental) |
| (optional) Group Name includes `HOOLI` | In Network | Richard Hendricks (UnitedHealthcare): ties with the UnitedHealthcare rule, the two disagree, so the result is `INDETERMINATE` with both rules listed |

Results come back ordered in network, then indeterminate, then out of network, so Richard Hendricks returns his Aetna plan first and Jack Barker his Medicare plan first.
